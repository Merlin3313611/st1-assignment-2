# Reflection

Before using AI, I had built a simple prototype that stored two hardcoded appointments and printed them., it had worked but it had no validation, structure or a way to detect its mistakes such as duplicate booking. By using AI, it helped me understand how to organize the code into function, validate them properly and to think about edge cases such as blank name or strange time formats, it also highlighted limitations which i hadn't considered in the beginning like duplicate bookings for the same practitioner and time. The AI did make some assumptions, such as suggesting extra validation and time parsing, but these were reasonable and easy to adapt.

To verify the AI output, I ran the program with normal inputs, blank names, duplicate bookings, and `None` values. I checked that errors were raised correctly and that the appointment list updated as expected. The engineering work such as  debugging, verifying behavior, and making sure the program met the assignment constraints still remained my responsibility.
